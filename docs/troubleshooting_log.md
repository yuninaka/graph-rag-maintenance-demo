### 2026-08-30 Q5

- **質問**: コンベアBが停止した原因を全て教えてください
- **期待した回答の要素**: `モーター`, `詰まり`, `絶縁不良`, `取り付けボルト`
- **実際の回答**: `モーターのコイル絶縁不良`、`近接センサーの経年劣化`、`搬送物の角部品との接触による局所摩耗`の3件のみ(score=0.75)。期待に含まれる「取り付けボルト」(R005)が欠落。
- **原因の仮説**:
  - [x] グラフのノード/エッジ設計に不足(例: ある関係が表現できていない)
  - [ ] Cypher生成(text-to-Cypher)の精度不足
  - [ ] ベクトル検索のチャンク粒度が不適切
  - [ ] Agentのツール選択ミス(vector/graphの判断を誤った)
  - [ ] プロンプト(システムプロンプト/ツール説明文)の曖昧さ
- **対応**: `build_knowledge_graph.py` の抽出方式が `claude_code` の場合、元データの正規化済み `record["equipment"]` (例: `コンベアB`) で上書きせず、LLMが本文から自由記述抽出した設備名をそのまま使用している(`rule_based` モードのみ上書き処理あり)。そのためR005が「コンベアBのモーター」、R026が「コンベアB ベルト駆動プーリー」という別Equipmentノードに分裂し、`Equipment {name: 'コンベアB'}` の完全一致クエリから漏れる。**対応: `main()` 内で抽出方式によらず常に `equipment=record["equipment"]` を使用するよう修正済み**(コミット対象)。Neo4jを全削除し再構築して反映。
- **対応後の再評価結果**: Equipmentノードが8設備・8ノードに統合されたことを確認。全体平均スコアは0.77→0.86に改善(graph: 0.58→0.75)。
- **追加対応(golden_qa.jsonl側の誤り)**: Q5の期待キーワード「詰まり」を報告書原文(R008)で確認したところ、「搬送物の詰まりは**見当たらず**」と否定形で言及されているだけで実際の原因ではなかった。また実際の第3の停止原因である「近接センサー」(R017)が期待キーワードから漏れていた。R017本文が「前回(R005)は取付ボルトの緩み、前々回(R008)はモーターのコイル絶縁不良」と明示的に振り返っているため、コンベアBの「停止」原因はR005・R008・R017の3件と特定できる(R026・R034は本文中で明示的に別トラブルと区別されている)。`expected_keywords` を `["モーター", "取り付けボルト", "絶縁不良", "近接センサー"]` に修正。再評価でscore 0.75→1.00に改善(全体平均0.86→0.89)。

### 2026-08-30 Q9

- **質問**: ポンプ3号機で吐出圧力低下が発生した原因は何回、それぞれ何が原因でしたか？

- **原因の仮説**:
